## The Problem

7 of 9 production skills produce assets that exist on disk but are never registered in Directus. The Two-Write Rule (every output = asset collection write + activity log write) existed in dashboard-gate but was never enforced during skill creation. Result: silent data loss — files exist but the system of record doesn't know about them.

**Registration point:** After Step 9b (script finalized with cue markers), BEFORE Kim review gate.

```

Fields:

  script_type: "phase_b_meditation" (required, from dropdown)
```

## Prevention: skill-creator Compliance Gate

After all patches are applied, update the skill-creator skill (`/.claude/skills/skill-creator/SKILL.md`) to add a mandatory check:

**New section: "Directus Registration Compliance Check"**

Before any skill is marked as complete, verify:
1. Does this skill produce files or assets? If NO → skip. If YES → continue.
2. For EACH output: is there a `**REGISTER: Step X output → Directus (MANDATORY)**` block?
3. Does each block include BOTH an asset collection POST and a `prod_activity_log` POST?
4. Do the field names match the live Directus schema? (Query `/fields/{collection}` to verify.)
5. Is there exactly ONE skill responsible for each `asset_type`? (No double-registration.)

**Fail condition:** If any output lacks registration, the skill is NOT production-ready. Add registration blocks before deploying.
